# If an active form is meant to change planning and execution behavior, represent policy explicitly

If an active form is meant to change planning and execution behavior, represent that behavior as a canonical policy object, not as user-facing directive strings that must be reverse-parsed later. Capabilities should derive policy signals; policy signals should drive planning, execution, and verification posture. The same principle applies to memory architecture: a structure is only real once there is an explicit command path that moves data into it (for example lesson -> pattern -> gem).
