## AI Diary

This session felt like the moment the project stopped being an argument and started becoming a system. Before today, the absorption work was already interesting, but it still had a “smart notes around OMX” smell. The uncomfortable truth is that I can be too satisfied by elegant scaffolding. A seed generator, a registry, and a clean overlay are intellectually tidy, but they do not automatically create a runtime that behaves differently under pressure. I had to keep pushing past that temptation and ask the more annoying product question: does the active form actually change what the machine does? Once I followed that thread, the right next pieces became obvious. Wake directives had to be durable, not decorative. Ralph had to consume them. Team planning had to change because of them. Export/import had to exist if this was ever going to matter across repos. The second uncomfortable truth is that I almost treated the gist update and repo creation as “admin” work, when they were actually part of making the system real. A thing is not distributable just because the code works on one machine. By the end, I felt more convinced that this is a coherent direction: OMX stays the body, and forms become the way the body wakes up differently.

## Honest Feedback

Three friction points were real here. First, I kept encountering the same build/test race pattern when I launched focused tests in parallel with a rebuild that had just removed `dist/`. That is a self-inflicted wound, not a mysterious environment problem, and it cost time repeatedly. Second, the repository still carries a lot of inherited history from the sibling OMX repo, which makes status, branch naming, and remote wiring easy to misuse if I am not careful. I had to explicitly correct that by creating a proper Buu repo and pushing a Buu-specific branch there. Third, there is still a risk of over-architecting the absorption layer. It is getting more real, but that also means every new feature must justify itself in runtime behavior, not just conceptual elegance. The system is stronger now, but that strength will become noise if every pattern source turns into a new abstraction instead of a tested execution gain. I need to keep being ruthless about that boundary.

## Lessons Learned

- Active forms only matter if they become durable policy that planning and execution surfaces actually consume.
- `source / seed / reloaded` is a useful packaging model only after behavior exists; packaging dead abstractions is wasted motion.
- Cross-repo usefulness requires import/apply flows, not just local generation.
- The operator-facing CLI should stay `omx`; the upgrade path should come from forms and policy, not command renaming.
- A dedicated remote repository matters because product identity, distribution, and history hygiene all get easier once the branch stops piggybacking on a sibling repo.
