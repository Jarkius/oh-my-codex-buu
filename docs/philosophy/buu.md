# Buu Philosophy

## Core Idea

`oh-my-codex-buu` does not replace the OMX body. It evolves it.

The project uses two Dragon Ball absorption models at different layers:

- **Cell** for safety
- **Buu** for power

## Cell Layer

Cell is the digestion system:

- fetch external material
- quarantine it
- inspect its structure
- approve or reject
- preserve provenance

Cell is disciplined, selective, and compatibility-first.

## Buu Layer

Buu is the absorption and transformation system:

- engulf whole capability bundles
- preserve them as cocoons
- inherit their powers and patterns
- activate fused forms selectively
- keep absorbed identities traceable rather than pretending they vanished

## Why Both

Using Buu without Cell creates corruption.
Using Cell without Buu creates a timid system that can only blend incrementally.

The intended architecture is:

1. Cell digests
2. Buu cocoons
3. Forms activate

## Software Translation

- **Cocoon**: absorbed repo, skill bundle, workflow pack, or prompt pack
- **Registry**: source of truth for absorbed artifacts
- **Form**: active composition of selected cocoons
- **Provenance**: who was absorbed, when, from where, and under what compatibility result

## Design Rule

Do not blindly copy another system into this one.

Absorb it, preserve it, and activate only the powers we can explain.
